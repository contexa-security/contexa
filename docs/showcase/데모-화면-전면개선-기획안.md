  6. 메뉴 이름과 모든 설명 · 소개 · 제목 · 질문을 보안 비즈니스 용어로 바꾼다.

## 1. 현행 화면 전수 분석

### 1.1 방법

- 현행 64화면을 한 · 영 두 언어와 1440 · 390 두 폭으로 Playwright로 열었다(256캡처, 실패 0).
- 자동 측정 항목
  - 글자 크기 · 굵기, 모서리, 테두리 · 배경색, 세로 간격, 버튼 높이, 아이콘 크기
  - 낮은 대비 글, 접기 수, 내용이 빈 넓은 상자
  - 첫 화면 글자 수, 쪽 높이, 왼쪽 정렬선 수
- 그다음 1440 원래 해상도 사진으로 화면마다 눈 검수를 했다(1.4).
- 시안도 같은 측정 도구로 쟀다(같은 기준으로 비교하기 위해).

### 1.4 눈 검수 요지 (1440 원래 해상도)

- **시작 · 고르기**: 화면의 70%가 빈 어둠이다. 카드 오른쪽 절반이 비어 있고, 제목 · 설명이 같은 20px · 같은 색이다. 정렬이 화면마다 다르다(가운데 · 왼쪽).
- **실시간 판정(2-2)**: 한 패널에 표현이 9가지 섞여 있다. 기울어진 "추가 인증" 도장은 장난스럽고, 두 열의 높이가 맞지 않는다.
- **결과(2-3)**: 1,010px짜리 빨간 막대 4개가 화면을 덮는다. 가장 중요한 Contexa 행은 거의 보이지 않는 빈 막대다.
- **판정 근거(3-3)**: 한 카드에 글꼴 2가지, 언어 2가지, 크기 3가지가 섞여 있다. 사실 기호(F4 · P1)에 설명이 없다.
- **가능성 비교(5-3)**: 판정 글자보다 숫자(44px)가 커서 위계가 뒤집혀 있다. 꼬리표 모양이 3가지다.
- **벤치마크**: 912px 기둥에 글 문단이 쌓여 있다. 결론이 문장 속 숫자이고, 측정 시점 · 표본 한계가 첫 화면에 없다.
- **실행 상세**: 바탕 화면 없이 960px 모달만 뜬다. 알약형 탭 7개가 다른 화면의 탭과 모양이 다르다.
- **휴대폰**: 6단계 네모 버튼 줄이 맨 위를 차지하고, 두 줄로 꺾인 알약 버튼(약 100px)이 화면을 덮는다.

## 2. 참고 화면 평가와 넘어설 지점

- **참고 화면의 장점**: 틀 · 탐색 · 일관성은 좋은 표준 관리자 템플릿 수준이다(고정 왼쪽 메뉴, 공통 페이지 머리, 탭, 필터 막대, 수치 카드, 표, 오른쪽 상세, 모달은 상세에만).
- **약점**
  - 표 머리 · 보조 글이 작고 흐려 대비가 약하다.
  - 수치 카드의 절반이 빈칸이다.
  - 일 단위 값을 곡선으로 이어 없는 값을 그린다.
  - 오류 원문을 표 칸에 그대로 쏟는다.
  - 뱃지 · 비활성 버튼 · "…" 행 동작이 작거나 뜻이 불분명하다.
  - 범용 템플릿이라 제품 고유의 표현이 없다.
- **Contexa의 방향**: 이 기본기를 갖추고, 그 위에 **분명한 위계, 목적 있는 밀도, 사실대로 그리는 차트, 판정 → 근거 → 원문의 고유한 표현**을 더한다.
- 틀을 베끼지 않는다. 화면 하나하나는 Contexa의 내용에 맞게 새로 설계한다.

## 3. 설계 원칙

| ID | 원칙 |
|---|---|
| P-1 | **메뉴의 성격대로 만든다.** 실행형(위협 시뮬레이션 4메뉴)은 단계 표시를 쓴다. 조회형(판정 이력 · 운영 지표 · 벤치마크 · 시나리오 검증)은 필터 · 표 · 탭, 설명형(보안 현황 · AI 판정 엔진 · 도입 가이드)은 탭과 카드로 만든다. 성격이 다른 화면을 이전 · 다음으로 잇지 않는다 |
| P-2 | **첫 화면에 결론을 둔다.** 화면마다 맨 위 카드에 그 화면의 답(판정, 핵심 수치, 이유 한 줄)을 둔다 |
| P-3 | **접기 · 모달은 예외로만 쓴다**(13절). 판정 · 이유 · 수치 · 표본/한계는 절대 접지 않는다 |
| P-4 | **같은 정보는 같은 모양으로 보인다.** 판정 뱃지 5종, 평가 뱃지 5종, 실행 ID 코드 칩, 수치 카드, 시각 형식은 모든 화면에서 같다 |
| P-5 | **한 화면에는 한 목적만 둔다.** 탭 하나가 한 질문에 답한다 |
| P-6 | **실제 데이터만 쓴다.** 화면의 숫자는 포털 응답이나 원자료 값이고, 표본 · 기간 · 출처를 숫자 옆에 함께 둔다 |
| P-7 | **세계 수준의 기본기를 갖춘다.** 한 · 영 같은 배치, WCAG 2.2 AA, 키보드 접근, 다크 · 라이트, 1440 · 1280 · 1024 · 768 · 390에서 넘침 0 |
| P-8 | **사실은 지우지 않는다**(Q-84). 옛 화면의 사실은 모두 새 위치로 옮긴다(11절) |

### 7.0 체험 흐름 (v3) — 데모 시작 · 위협 시나리오 선택 · 4단계 · 같은 요청 비교

**왜 다시 설계했나**: v2는 메뉴 · 탭 · 조회 화면을 잘 갖췄지만, 처음 온 방문자에게는 관리 콘솔로 보였다. 첫 화면이 대시보드였고, 메뉴 13개가 같은 무게였으며, 실행 화면은 읽을 것이 많았다. 현행 화면의 장점(버튼 하나로 시작 · 한 화면 한 결정 · "같은 계정, 같은 요청"이라는 이야기)은 살리고, 현행의 약점(빈 화면 · 정보 없는 카드 · 접힌 요청 · 빨간 막대 반복)은 없앤다.
