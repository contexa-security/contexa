# CONTEXA Anthropic Glasswing 참여 전략서

작성일: 2026-04-13
작성 기준: 2026-04-13 기준 Anthropic 공식 자료, CONTEXA 코드베이스, 공개 운영 자산 분석

## 1. 목적

이 문서의 목적은 CONTEXA가 Anthropic `Project Glasswing`와 직접적인 launch partner 또는 Mythos Preview 사용 조직이 되는 것을 당장 목표로 삼지 않고, 우선적으로 `Anthropic가 Glasswing 접근 검토가 가능한 플랫폼으로 CONTEXA를 수용하도록 만드는 전략`을 정리하는 것이다.

최우선 1차 목표는 다음과 같다.

`Anthropic가 CONTEXA를 Glasswing와 구조적으로 연결 가능한 오픈소스 런타임 보안 플랫폼으로 인식하고, 향후 관련 access 또는 review 대상에 포함할 수 있는 플랫폼으로 받아들이는 것`

## 2. 핵심 해석

Anthropic의 Glasswing 발표문은 오픈소스 maintainers에 대해 `access`를 원하면 `Claude for Open Source` 프로그램을 통해 신청하라고 안내한다. 따라서 `Claude for Open Source`는 원래 `6개월 Claude Max 20x` 지원 프로그램이 맞지만, Glasswing 맥락에서는 `오픈소스 유지관리자의 access intake 창구` 역할도 겸한다고 해석하는 것이 타당하다.

정리하면 다음과 같다.

- `Claude for Open Source`
  - 기본 기능: OSS maintainers 지원 프로그램
  - 추가 의미: Glasswing 관련 maintainers가 접근 검토를 요청하는 공식 신청 경로

다만 아직 공식적으로 확정되지 않은 부분도 있다.

- 일반 OSS 심사와 Glasswing 관련 검토가 내부적으로 완전히 같은 로직인지
- Claude Max 승인과 Glasswing 관련 access consideration이 같은 단계인지
- Mythos Preview 접근까지 직접 연결되는지

따라서 CONTEXA의 목표는 `직접 접근 요구`가 아니라 `검토 대상에 들어가는 것`으로 잡아야 한다.

## 3. 목표 구조

### 3.1 1차 목표

Anthropic가 CONTEXA를 다음과 같이 받아들이는 것이다.

- 단순한 개인 프로젝트가 아님
- 보안적으로 의미 있는 오픈소스 플랫폼임
- Glasswing가 여는 시장과 구조적으로 연결되는 하류 runtime control plane임
- 따라서 향후 access, review, verification, standards 대화의 검토 대상이 될 수 있음

### 3.2 2차 목표

Anthropic와의 직접 대화 가능성을 확보하는 것이다.

- Anthropic Security / Partnerships 검토
- 향후 `Cyber Verification Program` 또는 유사 cohort 검토

### 3.3 3차 목표

장기적으로 아래 중 하나 이상으로 이어지는 것이다.

- Glasswing 관련 maintainer access 검토
- Cyber Verification Program 진입
- Anthropic standards / recommendations 논의에서 참고 사례로 포함
- Claude Partner Network와 별도 검토

## 4. Anthropic-facing public surfaces

Anthropic에 처음 노출하는 공식 공개면은 아래 4개로 제한한다.

- 메인 사이트: `https://ctxa.ai`
- 문서 사이트: `https://docs.ctxa.ai`
- 공개 벤치마킹 진입점: `https://ctxa.ai/benchmark`
- 공개 보안 연락면: `https://ctxa.ai/.well-known/security.txt`

초기 1차 패키지에서 제외할 것:

- `demo.ctxa.ai`

제외 이유는 기능 부족이 아니라 첫 인상 때문이다. `demo.ctxa.ai`는 admin console 중심으로 읽힐 가능성이 높고, CONTEXA를 `IAM admin SaaS`처럼 오해하게 만들 수 있다. Anthropic 초기 노출면에서는 CONTEXA의 정체성을 `runtime zero-trust control platform`으로 고정하는 것이 더 중요하다.

## 5. Anthropic 공식 자료 기준 현재 상황

### 5.1 Project Glasswing의 본질

Anthropic `Project Glasswing`는 AI 기반 취약점 탐지와 defensive cyber 작업을 critical software 영역에 적용하려는 프로젝트다.

핵심 메시지:

- Mythos Preview는 취약점 탐지, black-box testing, binaries, endpoint security, penetration testing에 강하다
- launch partners와 추가 critical software 조직들이 참여 중이다
- Linux Foundation의 Alpha-Omega, OpenSSF, Apache Software Foundation을 지원한다
- maintainers interested in access는 `Claude for Open Source`를 통해 신청할 수 있다
- 90일 공개 보고, practical recommendations, standards, third-party body까지 언급한다

### 5.2 Claude for Open Source의 현재 의미

Anthropic OSS 프로그램은 정량 기준을 둔다.

- public repo
- `5,000+ GitHub stars` 또는 `1M+ monthly NPM downloads`
- 최근 3개월 유지관리 활동

하지만 공식 문구는 기준 미달 프로젝트에도 `apply anyway`를 열어 두고 있다. 따라서 CONTEXA는 `정량 자격`보다 `구조적 relevance`와 `security infrastructure value`로 평가받아야 한다.

## 6. CONTEXA의 현재 위치

### 6.1 Anthropic에게 보여줄 수 있는 강점

CONTEXA는 Glasswing와 같은 레이어에 있지 않지만, 바로 그 이유로 가치가 있다.

- Glasswing / Mythos
  - 취약점 발견
  - 바이너리 분석
  - 악용 가능성 파악
  - critical software hardening
- CONTEXA
  - 인증 이후 request-time 통제
  - workload / service client 통제
  - delegated agent 실행 통제
  - MCP / A2A / OIDC workload continuity
  - exploit-window compensating control
  - verification / benchmark / publication proof

즉 CONTEXA는 `Glasswing와 경쟁하는 제품`이 아니라 `Glasswing가 발견한 위험을 운영 통제로 연결하는 하류 control plane`이다.

### 6.3 현재 약점

Anthropic 검토 기준에서 불리한 요소도 분명하다.

- GitHub stars, contributors, 다운로드 지표가 약하다
- `contexa-enterprise`는 공개 OSS 패키지가 아니다
- code vulnerability / binary analysis 직접 결과물이 아니다
- 대외 생태계 의존도에 대한 공개 숫자가 아직 약하다

즉 `자동 수용`을 기대하면 안 되고, `왜 검토해야 하는가`를 구조적으로 설득해야 한다.

## 7. 질문별 최종 판단

### 7.1 Glasswing 직접 참여가 가능한가

지금 당장 직접 참여를 목표로 두는 것은 비현실적이다.

현실적인 목표는 다음과 같다.

- `Claude for Open Source`를 통해 Glasswing 관련 maintainers review 대상으로 들어가는 것
- Anthropic가 CONTEXA를 `runtime downstream complement`로 인식하는 것
- 향후 Cyber Verification Program 검토 대상으로 들어가는 것

### 7.2 stars 0, contributors 0이면 검토되겠는가

정량 기준만 보면 불리하다.

하지만 다음 이유로 검토는 가능하다.

- 공식 문구가 기준 미달 프로젝트의 예외 신청을 허용한다
- CONTEXA는 일반 애플리케이션이 아니라 runtime security platform이다
- Glasswing가 여는 upstream 시장과 구조적으로 연결된다

따라서 목표는 `수용 보장`이 아니라 `검토 명분 확보`다.

### 7.3 운영 사이트와 문서 사이트가 있으면 도움이 되는가

그렇다. Anthropic가 볼 수 있는 신뢰 요소다.

- 공개 메인 사이트
- 공개 문서 사이트
- 공개 benchmark/report
- RFC 9116 security.txt
- SECURITY.md / CONTRIBUTING.md 같은 운영 자산

단, `demo.ctxa.ai`는 초기에 앞세우지 않는다.

### 7.4 post-auth runtime zero trust의 중요성을 제안하면 관심 대상이 될 수 있는가

그럴 수 있다. 다만 framing이 중요하다.

좋은 framing:

- Glasswing는 upstream에서 위험을 발견한다
- exploit window는 여전히 runtime에 남아 있다
- 이미 인증된 human, workload, delegated agent를 어떻게 줄일 것인가
- CONTEXA는 그 runtime compensating control 계층이다

### 7.5 검증 콘솔과 벤치마킹이 명분이 되는가

그렇다. 매우 강한 명분이 된다.

Anthropic 입장에서 중요한 것은 단순 주장보다 `proof-backed system`이다. CONTEXA는 runtime control을 말하는 것에서 멈추지 않고 verification과 benchmark publication으로 증명한다. 이건 특별 검토 사유로 충분하다.

## 8. 최적 전략

### 8.1 전략 요약

가장 중요한 메시지는 하나다.

`우리는 Glasswing에 직접 들어가겠다고 말하는 것이 아니다. Glasswing와 구조적으로 연결되는 플랫폼이므로 향후 access consideration을 받을 자격이 있다고 설명하는 것이다.`

### 8.2 실행 경로

1. `Claude for Open Source`로 신청
2. 신청서에 `Glasswing-related access consideration`을 명시
3. 별도 direct outreach memo를 Anthropic에 전달
4. `future Cyber Verification Program candidate`로 포지셔닝

### 8.3 Anthropic에게 전달할 최종 문장

`We are not asking Anthropic to treat CONTEXA as a current Glasswing partner. Our immediate goal is narrower and more realistic: to have CONTEXA recognized as an open-source runtime security platform that is structurally relevant to Glasswing and therefore worth review for future access, verification, or standards-related participation.`

## 11. 최종 결론

CONTEXA의 현재 최우선 목표는 `Glasswing에 직접 참여`가 아니다.

정확한 1차 목표는 다음과 같다.

`Anthropic가 CONTEXA를 Glasswing와 구조적으로 연결 가능한 오픈소스 런타임 보안 플랫폼으로 받아들이고, 향후 관련 access 또는 review 대상이 될 수 있는 프로젝트로 인식하는 것`

이 목표는 현실적이고, 지금 준비하면 충분히 전달 가능한 수준이다.
