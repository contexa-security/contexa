# CONTEXA Anthropic Glasswing 참여 전략서

작성일: 2026-04-13
작성 기준: 2026-04-13 기준 Anthropic 공식 자료, CONTEXA 코드베이스 및 공개 운영 자산 분석

## 1. 이 문서의 목적

이 문서의 목적은 CONTEXA가 Anthropic의 `Project Glasswing`와 직접적인 launch partner나 Mythos Preview 사용 조직이 되는 것을 당장 목표로 삼지 않고, 우선적으로 `Anthropic가 Glasswing 접근 검토가 가능한 플랫폼`으로 CONTEXA를 수용하도록 만드는 전략을 정리하는 것이다.

즉 최우선 1차 목표는 다음과 같다.

`Anthropic가 CONTEXA를 Glasswing와 구조적으로 연결 가능한 오픈소스 런타임 보안 플랫폼으로 인식하고, 향후 관련 access 또는 review 대상에 포함할 수 있는 플랫폼으로 받아들이는 것`

이 문서는 그 목적에 맞게 참여 가능성, 제안 방식, 준비 우선순위를 정리한다.

## 2. 가장 중요한 정정

이전 해석에서 과도하게 분리해서 본 부분을 바로잡는다.

Anthropic의 Glasswing 발표문은 오픈소스 maintainers에 대해 `access`를 원하면 `Claude for Open Source` 프로그램을 통해 신청하라고 안내한다. 따라서 `Claude for Open Source`는 원래는 `6개월 Claude Max 20x` 지원 프로그램이 맞지만, Glasswing 맥락에서 보면 `오픈소스 유지관리자의 access intake 창구` 역할도 겸한다고 해석하는 것이 맞다.

즉 다음처럼 보는 것이 가장 정확하다.

- `Claude for Open Source`
  - 기본 기능: OSS maintainers 지원 프로그램
  - 추가 의미: Glasswing 관련 maintainers가 access 의사를 제출하는 공식 신청 경로

다만 여전히 공식적으로 확정되지 않은 부분도 있다.

- 신청 후 심사 로직이 일반 OSS 심사와 Glasswing 검토를 완전히 공유하는지
- Claude Max 지원 승인과 Glasswing 관련 access 검토가 동일한 결론으로 묶이는지
- Mythos Preview 자체 접근이 어느 단계까지 열려 있는지

따라서 전략은 다음처럼 잡아야 한다.

- `Claude for Open Source`로 신청한다
- 그러나 신청 메시지는 `무료 Claude 혜택 신청`이 아니라 `Glasswing 맥락에서 검토 가능한 플랫폼`임을 설득하는 방향으로 쓴다

## 3. 최종 목표 구조

### 3.1 1차 목표

Anthropic가 CONTEXA를 다음과 같이 받아들이는 것.

- 단순한 개인 프로젝트가 아니다
- 보안적으로 의미 있는 오픈소스 플랫폼이다
- Glasswing가 여는 시장과 구조적으로 연결되는 하류 runtime control plane이다
- 따라서 향후 access, review, verification, standards 논의의 검토 대상이 될 수 있다

### 3.2 2차 목표

Anthropic와의 직접 대화 가능성 확보.

- direct outreach 답변
- Anthropic Security / Partnerships 팀의 검토
- future `Cyber Verification Program` 또는 관련 cohort 검토 가능성 확보

### 3.3 3차 목표

장기적으로 아래 중 하나 이상으로 이어지는 것.

- Glasswing 관련 maintainer access 검토
- Cyber Verification Program 진입
- Anthropic standards / recommendations 논의에 참고 사례로 포함
- Claude Partner Network 관점의 별도 검토

## 4. Anthropic 공식 자료 기준 현재 상황

### 4.1 Project Glasswing의 의미

Anthropic의 `Project Glasswing`는 AI 기반 취약점 탐지와 defensive cyber 작업을 critical software 영역에 적용하려는 프로젝트다.

핵심 내용:

- Mythos Preview는 취약점 탐지, black-box testing, binaries, endpoint security, penetration testing 등에서 강함
- launch partners와 일부 추가 조직이 참여 중
- Linux Foundation의 Alpha-Omega, OpenSSF, Apache Software Foundation 지원 발표
- maintainers interested in access는 `Claude for Open Source`를 통해 신청 가능
- 90일 공개 보고, practical recommendations, standards, third-party body까지 예고

### 4.2 Claude for Open Source의 현재 의미

Anthropic의 OSS 프로그램은 정량 기준을 둔다.

- public repo
- `5,000+ GitHub stars` 또는 `1M+ monthly NPM downloads`
- 최근 3개월의 유지관리 활동

하지만 공식 문구는 기준 미달 프로젝트도 `If you maintain something the ecosystem quietly depends on, apply anyway and tell us about it.` 라고 열어 두고 있다.

따라서 CONTEXA는 다음 논리로 접근해야 한다.

- 정량 조건은 약하다
- 그러나 보안적으로는 중요한 infrastructure 성격을 가진다
- Glasswing가 여는 upstream 시장과 직접 연결되는 downstream runtime control plane이다
- 그래서 일반 OSS 신청자가 아니라 `special review candidate`로 검토받는 것이 목표다

## 5. CONTEXA의 현재 포지션

### 5.1 Anthropic에게 보여줄 수 있는 강점

CONTEXA는 Glasswing와 다른 레이어에 있으나, 바로 그 이유 때문에 의미가 있다.

- Glasswing / Mythos
  - 취약점 발견
  - 바이너리 분석
  - 악용 가능성 파악
  - critical software hardening
- CONTEXA
  - 인증 이후 인간 요청 통제
  - workload / service client 통제
  - delegated agent 실행 통제
  - MCP / A2A / OIDC workload continuity
  - exploit-window compensating control
  - verification / benchmark / publication proof

즉 CONTEXA는 `Glasswing와 경쟁하는 제품`이 아니라 `Glasswing가 발견한 위험을 운영 통제로 연결하는 하류 제어 계층`이다.

### 5.3 현재 약점

Anthropic 검토 기준에서 불리한 요소도 분명하다.

- GitHub stars, contributors, 다운로드 지표가 약함
- `contexa-enterprise` 공개 OSS 패키징 자산이 얇음
- code vulnerability / binary analysis 직접 산출물은 없음
- 대형 생태계 의존도에 대한 외부 증거가 아직 약함

즉 `자동 수용`을 기대하면 안 되고, `특별 검토 사유`를 정교하게 써야 한다.

## 6. 질문에 대한 최종 판단

### 질문 1. Mythos에 직접 참여할 수 있겠는가

당장 직접 참여를 목표로 두는 것은 현실적이지 않다.

하지만 다음은 현실적이다.

- `Claude for Open Source`를 통해 Glasswing 관련 maintainers access 검토 대상이 되는 것
- Anthropic가 CONTEXA를 `runtime downstream complement`로 인식하는 것
- 향후 Cyber Verification Program 검토 대상이 되는 것

따라서 목표는 `Mythos direct access`가 아니라 `Glasswing-related access consideration`이어야 한다.

### 질문 2. stars 0, contributors 0이면 검토되겠는가

정량 조건만 보면 불리하다.

그러나 Glasswing 관련 신청이라면 아래 사유로 검토될 가능성은 있다.

- 공식 문구상 기준 미달 프로젝트도 신청 가능
- CONTEXA는 일반 웹앱이 아니라 runtime security platform임
- Anthropic가 지금 여는 시장과 구조적으로 연결됨

즉, 수용 보장은 없지만 `검토 명분`은 충분히 만들 수 있다.

### 질문 3. 운영 사이트와 문서 사이트가 있으면 의미가 있는가

예. 의미가 있다.

Anthropic가 볼 수 있는 신뢰 요소:

- 공개 문서
- 운영 중인 공식 사이트
- public benchmark/report
- RFC 9116 security.txt
- SECURITY.md / CONTRIBUTING.md 같은 유지관리 신뢰 자산

이건 stars를 대체하지는 않지만, `serious platform`으로 보이게 만드는 데 중요하다.

### 질문 4. post-auth runtime zero trust의 중요성을 제안하면 관심 대상이 될 수 있는가

예. 이게 핵심 제안이어야 한다.

다만 “행동패턴 이상감지 모델이 필요하다”로 시작하면 안 된다.

더 좋은 framing:

- Glasswing는 upstream에서 위험을 발견한다
- 실제 exploit window는 여전히 runtime에서 열려 있다
- 이미 인증된 human, workload, delegated agent를 어떻게 줄일 것인가
- CONTEXA는 그 runtime compensating control 계층이다

Anthropic에게는 이 framing이 자연스럽다.

### 질문 5. 검증 콘솔과 벤치마킹이 명분이 되는가

예. 아주 강한 명분이 된다.

Anthropic 입장에서 중요한 것은 단순 주장이 아니라 `proof-backed system`이다. CONTEXA는 runtime control을 그냥 말하는 것이 아니라 verification과 benchmark publication으로 증명한다. 이건 특별 검토 사유로 충분히 쓸 만하다.

## 7. 최적 전략

### 7.1 전략 원칙

가장 중요한 원칙은 다음 하나다.

`우리는 Glasswing에 직접 들어가겠다고 말하는 것이 아니라, Glasswing와 구조적으로 연결되는 플랫폼이며 향후 access consideration을 받을 자격이 있다고 설득한다.`

### 7.2 실행 경로

1. `Claude for Open Source`로 신청
2. 신청서에 `Glasswing 관련 access 의사`를 명시
3. 별도 direct outreach memo를 Anthropic에 전달
4. `future Cyber Verification Program candidate`로 포지셔닝

### 7.3 Anthropic에게 전달할 최종 문장

`We are not asking Anthropic to treat CONTEXA as a current Glasswing partner. Our immediate goal is narrower and more realistic: to have CONTEXA recognized as an open-source runtime security platform that is structurally relevant to Glasswing and therefore worth review for future access, verification, or standards-related participation.`

## 10. 최종 결론

CONTEXA의 현재 최우선 목표는 `Glasswing에 직접 참여`가 아니다.

정확한 1차 목표는:

`Anthropic가 CONTEXA를 Glasswing와 구조적으로 연결 가능한 오픈소스 런타임 보안 플랫폼으로 받아들이고, 향후 관련 access 또는 review 대상이 될 수 있는 프로젝트로 인식하는 것`

이 목표는 현실적이고, 지금부터 준비하면 충분히 도달 가능한 수준이다.
