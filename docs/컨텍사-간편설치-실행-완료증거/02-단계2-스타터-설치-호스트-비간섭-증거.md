## 3. 9080 호스트 IAM 비간섭 실검증

동일 fixture를 baseline, starter-only, 명시적 SANDBOX, 명시적 FULL 순서로 매번 9080에서 기동했다. 무인증 요청은 모두 401이고 Basic 인증 요청은 모두 200이었다.

| 항목 | baseline | starter-only | SANDBOX | FULL + 기존 host chain |
| --- | --- | --- | --- | --- |
| principal | `host-admin` | 동일 | 동일 | 동일 |
| authenticated | `true` | 동일 | 동일 | 동일 |
| authority | `ROLE_HOST_ADMIN` | 동일 | 동일 | 동일 |
| Authentication 구현 | `UsernamePasswordAuthenticationToken` | 동일 | 동일 | 동일 |
| SecurityFilterChain bean | `hostSecurityFilterChain` 1개 | 동일 | 동일 | 동일 |
| filter 수와 순서 | 표준 11개 | byte-equivalent 구조 | byte-equivalent 구조 | byte-equivalent 구조 |
| Contexa bean 수 | 0 | 0 | 490 | 490 |

starter-only는 Contexa bean을 추가하지 않았다. 명시적 활성화에서는 플랫폼 bean이 생성되지만 host SecurityContext 계약은 baseline과 완전히 같았다. 기존 host `SecurityFilterChain`을 탐지한 FULL은 overlay에 `contexa.bridge.ownership=HOST_OWNED`와 `contexa.datasource.isolation.contexa-owned-application=false`만 기록하고 host datasource URL·계정·비밀번호를 기록하지 않았다. 서버 로그에서도 Contexa-owned authentication chain bootstrap이 HOST_OWNED 때문에 생략됨을 확인했다.

OSS 서버 기동이 현재 catalog 계약으로 seed를 완료했다. Enterprise migration이 의도적으로 비우는 legacy 행 수를 OSS 기동 필수조건으로 잘못 요구하던 검사는 제거했지만, 테이블 존재와 현재 catalog 수 검사는 유지했다. HCAD semantic cache는 Redis가 없는 standalone classpath에서 Redis 타입을 해석하지 않고 local 구현을 사용하며, distributed 조건에서만 Redis 구현을 등록한다. `@Lazy`나 `ObjectProvider`로 순환 또는 선택 의존성을 숨기지 않았다.

Phase 2는 CLI·starter·서버·DB 범위이며 관리 HTML/JS를 변경하거나 요구하지 않는다. 따라서 HTML/JS 브라우저 판정 항목은 해당 없음이다. 서버 HTTP와 SecurityContext, filter chain, DB는 실제 환경으로 검증했다.

- 최초 SANDBOX 기동 과정의 HCAD classpath·legacy seed count·Redis 선택 의존성 결함은 플랫폼 코드에서 원인을 수정하고 집중 테스트와 새 9080 기동으로 재검증했다. 실패 실행은 PASS 근거에 포함하지 않는다.
